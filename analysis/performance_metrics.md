# 性能指标：当前 35 条交付轨迹

来源：`jobs/kin/trajectory_eval/runs/kin_all_groups_v3`；七组各五题，每组对五条运行取算术平均。

- 原始工具调用：按工具调用 ID 计数，包含失败、读取、计划、轮询等调用；一个 shell 调用内的多条命令仍计一次。未按工作单元合并。
- 输入 Token 为累计输入总量，包含缓存命中及缓存写入；缓存列仅为命中读取量，属于输入的子集，不能再次相加。JSON/逐条 CSV 另列缓存写入量。
- DSH 以主会话 step_end usage 为基础，保留其已记录的重试消耗；按会话、turn、step 对齐原始 assistant/message，补回缺失步骤的 usage。缓存字段缺失时，仅在原始字段恰好解释 totalTokens 的差额时恢复；另外累加独立子会话 usage。所有补充都有原始记录，不估算。
- 输出 Token 使用日志 usage 口径；Gemini CLI 累加 output 与 thoughts，其他适配器使用 output_tokens/outputTokens，不重复加推理 Token。这不是只统计最终回答。
- 总耗时为 agent 阶段墙钟时间，包含运行中的工具等待、网络等待和重试；不含容器准备、独立几何判分和轨迹 Judge。并行执行的不同任务分别计时。
- Claude + DSH / kin1 是人工 continue：工具与 Token 只计算已合并的会话一次；耗时累加原运行和续跑段，排除两段间人工等待。
- 独立重跑只采用当前选中的那一次运行，不累计已废弃/被替代尝试的消耗。因此这些数值描述当前交付样本，不能解释为包含全部失败尝试的总成本。
- 不同工具封装的粒度不同；墙钟耗时还受服务延迟与重试影响，不能直接解释为纯模型推理速度。

人工续跑任务耗时修正：原段 722.346596 秒 + 续跑段 2936.503778 秒 = 3658.850374 秒。旧 trajectory_metrics.json 未修改。
